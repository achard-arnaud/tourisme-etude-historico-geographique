# Structuring chronological arcs

An ARC begins and ends when the governing optimum changes materially: political regime, resource system, spatial centre, security environment, trade architecture, legitimacy system, social-access architecture or external configuration.

Each arc records: entry rupture, causal question, drivers, amplifiers, consequences, non-causes, persistent structures, exit rupture and bridge to the next arc. Avoid ruler-by-ruler periodization unless succession changes the system.

## Vertical HIL threads
A mechanism such as caste, language, education, irrigation, religion or migration may persist across many arcs. Give it a stable thread ID/concept and reactivate it only where its role changes. Do not create a new chronological arc merely because new evidence appears for a persistent theme.

## Comparator anchoring
A comparator has a **home arc** in the main case. Attach it to the moment where the alternative institutional mechanism becomes analytically useful. Keep the comparator's own chronology sufficient to avoid anachronism, but do not let it displace the main country's temporal spine.

## Rupture test
Before splitting an arc ask: did incentives/capacity actually change, or did only leadership, rhetoric or evidence availability change? If the optimum remains stable, retain one arc and use a sub-section or vertical thread.

## Output
One `ARC.md` per period, scaffolded by `templates/arc.md` and `scripts/new_arc.py`, plus the vertical-thread ID for any mechanism reactivated across arcs.
