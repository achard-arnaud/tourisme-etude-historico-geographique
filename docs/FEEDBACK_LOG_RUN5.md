# Feedback log — Run 5

## User feedback converted into product requirements

### 1. Long projects need explicit recall of “where we stopped”
A correct historical answer is not enough if the user cannot tell whether the latest material is raw evidence, integrated research or already in the reader document.

**Promoted:** root state checkpoint, field-session checkpoint, promotion lifecycle and `CURRENT_OUTPUT_STATUS.md`.

### 2. New angles should refine the OS, not only the Sri Lanka example
The caste/social-mobility and comparative-development questions exposed reusable methods: social reproduction, access architecture, externalization of human capital, comparator scale and transportability.

**Promoted:** all relevant specialized skills were updated rather than encoding one-off Sri Lanka rules.

### 3. Comparators need mechanisms, not “country A did better” narratives
Tamil Nadu and Indonesia are useful precisely because they illuminate different instruments. They become misleading when outcomes are transported without market, federalism, war or institutional context.

**Promoted:** comparative gate, transportability test, comparator drift audit and scale normalization.

### 4. Wiki/graph must exist operationally if architecture claims they exist
Run 5 found a product gap: `03_wiki` and `04_graph` were part of the method but absent from the worked corpora.

**Promoted:** material wiki/graph in both Sri Lanka examples + QA rules for metadata, provenance and duplicate/source integrity.

### 5. Reader output must lag deliberately rather than silently
Fast field/research iteration can make an existing Word/PDF stale.

**Promoted:** canonical Markdown is now separately promotable; formatted export is regenerated only after the evidence/QA gate.
