# Run 27 — convergence implementation

Ce run ferme la dette de corpus révélée par Run 26 sans réutiliser le reader Run 25 comme input de rédaction.

Ordre contractuel :
1. archiver les sorties Run 26 from-scratch ;
2. corriger la résolution `return_to` et expliciter le statut de `canonical_points` ;
3. statuer le backlog de fragments terrain ;
4. créer un side story `method` stūpa / mudrā / lotus sourcé indépendamment des panneaux incertains ;
5. ajouter boucle de reprise + dispositions exhaustives + objectif de maximisation ;
6. produire manifeste claim-par-claim ;
7. refaire un from-scratch Run 27 et comparer au Run 25.

Un run n'est terminé que si chaque unité éligible possède une disposition explicite : `included`, `included_as_side_story` ou `not_selected_for_reader` avec motif. Aucun quatrième état silencieux n'est autorisé.
